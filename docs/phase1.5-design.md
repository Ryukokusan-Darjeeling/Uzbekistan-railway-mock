# Phase 1.5 设计研究：品级含权量 / 勾结分账 / 商人现金流

> 三项改动的研究结论。改动三（商人现金流）是地基——改动一、二的钱最终都从商人的月度现金流里出。

---

## 现状诊断

| 现状 | 问题 |
|---|---|
| `official.level: 3~5` | 只是存储字段，无任何逻辑使用；品级关系不存在 |
| `collude` 动作 | 官员单方吃"税基×10%"，商人无感、金额模糊、无双边关系 |
| `merchant.capital` | 初始 rand(500,3000) 后永不变化；无盈亏、无打点、无破产 |
| 贸易量公式 | `totalVolume × (1 − avgTax×1.5)` 抽象收缩，与商人个体无关 |

## 改动一：品级与含权量

### 1.1 品级表（真实清制）

| 职务 | 品级 | rankScore（越小越高） |
|---|---|---|
| 察哈尔都统 | 从一品（武职） | 2 |
| 钦差库伦办事大臣 | 特简大员，视正二品 | 4 |
| 库伦帮办大臣 | 从二品 | 5 |
| 汉黄德道（江汉关道） | 正四品 | 8 |
| 恰克图办事司员 | 从四品（章京衔） | 9 |
| 管理商民事务司员 | 正五品 | 10 |
| 张家口同知 | 正五品 | 10 |

rankScore = 品数×2 +（从？1:0），仅用于比较大小，不参与显示。

### 1.2 含权量 powerIndex（0~100，每月动态浮动）

```
powerIndex = 40 × 品级归一分（rankScore 反转归一）
           + 25 × 职务分（税关 1.0 / 口岸互市 0.9 / 转运 0.4）
           + 25 × 贸易量分（本城流经货值 / 全线最大城）
           + 10 × 政治资本 / 100
```

含权量是"活的"：贸易量萎缩、政治资本下跌都会实时压低含权量——被绕卡的税关官员权力真空化，这本身就是商路博弈的涌现结果。

### 1.3 制度性上下级（硬编码）

- 库伦办事大臣 → 库伦帮办大臣、恰克图两司员（边务系统）
- 察哈尔都统 → 张家口同知（察哈尔系统）

**每月孝敬（陋规，自动结算，非 LLM 动作）**：
```
孝敬额 = 下属上月灰色收入 × (0.10 + 0.10 × min(1, 上级含权量/80))
```
陋规是"必须交的惯例"，做成制度内自动结算而非 LLM 可选动作——保留 prompt 简洁度，且符合史实（陋规本是半制度化规费）。现有 `bribe` 动作保留，表示**额外**打点。

### 1.4 品级/含权量的四项规则影响

1. **克扣暴露概率** ×（1 − powerIndex/200）——高含权量官官相护，更难暴露
2. **考成**：政治资本项权重 ×（0.5 + powerIndex/100）
3. **勾结分账份额**（见改动二）
4. **孝敬流向**（见 1.3）

### 1.5 官员 prompt 增补

品级、含权量、上级（名字+品级）、下属名单、上月孝敬支出。动作集不变（6 个）。

## 改动二：勾结分账入私囊，金额清楚

### 2.1 从单方动作改为双边契约

现状 `collude` 是官员单方动作。新设计：

- 官员决策 `collude` 时**必须带 `target` 商人 id**（prompt 给出当月过境商人名单）
- 商人决策 `collude` 时可指定官员（双向都能发起，契约同构）

### 2.2 分账标的：当月实际避税额

```
避税额 = 该商人本月途经该官城市：应缴税 − 实缴税（勾结降税/放行走私）
官份额 = 0.35 + 0.003 × 官员 powerIndex   （约 35%~65%）
官得 = 避税额 × 官份额
商留 = 避税额 ×（1 − 官份额）
```

钱从商人省下的税里出（不是凭空印钱），官员 wealth、商人 capital 各加精确金额。

### 2.3 账目必须可读（事件日志格式）

```
[勾结] 常万达（晋商）× 张家口同知 王定安：本月避税 320 两，官得 192 两（六成），商留 128 两
```

### 2.4 契约延续与作废

- 契约登记进双方 `relationships`，**默认按月延续**（不每月重签）
- **换官即作废**——商人必须重新打点新官（"新官上任三把火"成本，勾结网络随 36 月流官周期洗牌，这是本设计最有戏剧性的涌现机制）
- 契约被考成发现（暴露的官员）→ 契约公开作废 + 商人损失信誉

## 改动三：商人月度现金流（地基）

### 3.1 每月每商人结算式

```
货值     shipment = min(capital × 0.8, 路线容量)
收入     revenue  = shipment × (卖价 100 − 路线成本) / 100
应缴税   taxDue   = Σ 途经城市 税率 × shipment
实缴税   taxPaid  = taxDue − 打点减免 − 勾结减免 − 走私豁免
打点     bribePaid（决策给出，付给指定城市官员，当月该城税率减半或放行）
风险损失 loss     = 概率(路线 baseRisk + 走私 0.15)触发 → 损失 shipment × 0.5（失窃/查扣）
净利     profit   = revenue − taxPaid − bribePaid − loss
capital += profit
```

### 3.2 破产与进场

- `capital < 100` → 破产退出商路（事件日志记一笔"常家商号折本歇业"）
- 3 个月后新商人从池中进场（姓名查重沿用 pickName 机制）

### 3.3 与现有系统的换血

| 旧公式 | 新来源 |
|---|---|
| `totalVolume × (1−avgTax×1.5)` | Σ 各商人 shipment（真实聚合） |
| `official._taxBase`（过境人数×抽象量） | 该城实缴税总额（真实留成） |
| 商人选路（利润静态比较） | 现金流模拟：规则商人选"净利期望最高"路线，税率>15% 的城市触发打点/走私倾向 |

### 3.4 商人 prompt 大改

输入：capital、上月盈亏明细、各城税率、现有契约、可打点官员名单。
动作带金额与目标：`{"action":"bribe","city":"zhangjiakou","amount":150}`、`{"action":"collude","target":"official_xxx"}`、`smuggle`、`route`、`hold`。

### 3.5 UI 呈现

- 商人卡：本金 + 上月盈亏（红涨绿亏按史实配色习惯反着来：盈用墨、亏用锈红）+ 打点支出
- 官员卡：品级徽记 + 含权量条 + 上月孝敬
- 事件日志：所有资金流一行一账

## 三改动耦合（设计的核心价值）

```
商人现金流 ──实缴税──→ 国库税基 ──考成压力──→ 官员
     │                                     ↑
     ├──打点/勾结分账──→ 官员私囊 ──孝敬──→ 上级私囊
     │
     └──加税 → 打点/勾结更划算 → 税基缩水 + 私囊膨胀（腐败的自我强化）
换官 → 契约作废 → 商人重新打点（周期性摩擦成本）
```

官员的每一两私囊都能溯源到具体商人的具体月份——"这条商道被谁、以何种方式、抽成了什么样子"从口号变成可对账的事实。

## 待拍板（附推荐）

1. **孝敬**：自动陋规（推荐）vs LLM 可选动作
2. **勾结契约**：按月延续至换官作废（推荐）vs 单月重签
3. **商人破产**：退出 + 延迟进场新商人（推荐）vs 保底续命
4. **品级表数值**：上表为史实参考值（都统从一品、同知正五品等），需确认
5. **风险损失触发**：概率模型（推荐，简单可控）vs LLM 叙事生成（贵且慢）

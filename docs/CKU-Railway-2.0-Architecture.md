## 0. 产品一句话

玩家旁观一条贯穿「清帝国 → 俄国 → 奥斯曼帝国 → 奥地利（哈布斯堡）」的真实欧亚商道，看一群自私的地方官员在各自的制度下谋私、换任、打点，看商人穿梭其中、商路兴衰，最终浮现出"这条商道被谁、以何种方式、抽成了什么样子"。

## 1. 世界观 · 真实地理与商路

### 1.1 四大政权与制度原型（写实）

| 政权 | 制度原型 | 官员核心动机 | 商人生态 |
|---|---|---|---|
| 清帝国 | 流官制 + 回避 + 捐纳 + 考成 | 短期掠夺、对上负责 | 晋商、徽商等行商帮 |
| 俄国 | 职级表（14 级）+ 军功晋升 | 向上抢功、忠于沙皇 | 官方特许商 + 俄商 |
| 奥斯曼帝国 | 包税制 iltizam / malikane | 过度榨取、可能世袭 | 希腊、亚美尼亚、犹太中间商 |
| 奥地利（哈布斯堡） | 开明专制 + 重商主义 | 国家经理人、国库至上 | 特许公司、航海商社 |

### 1.2 主商道（真实地名，可串通）

以下为完整节点网络，**每个城市都是一个可挂载官员/商人的节点**，节点间有真实的陆路、水路、海路连接：

**东段 · 清帝国（产茶 → 北运）**
- 产区：武夷山、安化、羊楼洞、汉口（"东方茶港"，长江总集散）
- 北运主线：汉口 → 樊城 → 赊旗 → 太原 → 张家口（张库大道起点）
- 出关：张家口 → 库伦（今乌兰巴托，蒙汉俄三方互市）→ 恰克图（中俄边贸口岸）

**中段 · 俄国（西伯利亚西行）**
- 恰克图 → 伊尔库茨克（"东方巴黎"，西伯利亚中转）→ 乌兰乌德 → 新西伯利亚 → 托木斯克 → 叶卡捷琳堡（欧亚分水岭）→ 喀山（伏尔加河枢纽）→ 莫斯科 → 圣彼得堡（终点/首都）

**南段 · 海路联运（俄商 19 世纪开辟，绕开陆路）**
- 汉口 → 上海 → 天津 → 海参崴 →（西伯利亚铁路后期）→ 圣彼得堡
- 汉口 → 苏伊士运河 → 黑海 → 敖德萨（黑海最大港，"俄国芝加哥"）→ 巴尔干 → 欧洲

**西段 · 奥斯曼 + 奥地利（欧亚咽喉）**
- 奥斯曼：阿勒颇（陆路集散）→ 安纳托利亚 → 君士坦丁堡（博斯普鲁斯/达达尼尔海峡咽喉）
- 奥地利：维也纳（多瑙河航运中心）→ 的里雅斯特（亚得里亚海自由港）
- 连接海路：敖德萨 ⇄ 君士坦丁堡 ⇄ 的里雅斯特（黑海—地中海航线，奥地利 Lloyd 航运、俄国义勇舰队）

> **串通机制**：上述节点构成一张连通图。陆路、水路、海路是三条可选路径，成本/风险/时效各异。商人（见 §4）会根据沿途税负、风险、时效自主选路，形成"陆路被抽干 → 商队改走海路 → 陆路口岸衰落"的历史重演（恰克图衰落的真实逻辑）。

## 2. 智能体角色（三类，均为自私个体）

### 2.1 官员（Officials）—— 核心博弈者

**私有状态**
```
Official {
  id, name, faction(清·满/清·汉/清·蒙/俄/奥斯曼/奥), post(官职), city(驻地),
  ethnicity(民族，决定官缺资格与命名),
  wealth(私囊), politicalCapital(政治资本),
  tenureRemaining(剩余任期, 清=36月),
  traits{ greed, riskAverse, loyalty, boldness },
  relationships[](上下级/亲属/商人/同行),
  utilityWeights{ wealth, capital, family, safety },
  privateMemory(长期目标/恩怨/秘密协议)
}
```

> **民族与官缺**：清朝官员必须带民族属性（满缺/汉缺/蒙缺），决定其能否出任某官位——边疆口岸（恰克图办事司员、库伦办事大臣）多为满缺或蒙缺，内地州县多为汉缺。换官时按"官缺"从对应民族的候选池抽取接班人，符合清代回避与官缺制的真实逻辑。俄、奥斯曼、奥地利的 `faction` 即国别，`post` 用其本国官衔（总督/省长/帕夏/贝伊/卡迪/财政大臣等）。

**目标函数（自私核心）**
```
Utility = w1·财富 + w2·政治资本 + w3·家族延续 + w4·人身安全 − w5·风险
```
- 清流官：w1 极高（三年刮地）、w3 中（打点传位给亲戚）
- 奥斯曼包税人：w3 极高（世袭 malikane）、w1 高（超额榨取差价）
- 俄国官僚：w2 极高（抢功晋升）
- 奥地利经理人：整体偏理性、低贪腐（对照组）

**可执行动作（由制度引擎裁决合法性）**
- 征税/加税/设卡、克扣上缴、虚报政绩、垄断某段转运
- 贿赂上司、捐纳买官、安插亲戚接班
- 与商人勾结分账、与邻地官员谈判/对抗
- 卖官鬻爵、勒索过境商队

### 2.2 商人（Merchants）—— 额外变量（新增）

商人不是官员，是**独立的理性套利者**，但同样可被官员拉拢、勒索、勾结。他们的存在让"官员加税"有了真实的传导对象和绕行空间。

**私有状态**
```
Merchant {
  id, name, origin(晋商/俄商/希腊商/犹太商/意大利商...),
  capital(本金), goods[](货物组合),
  route(当前路线), loyalty(对某官员的依附),
  network[](各地联系人/靠山),
  traits{ riskAverse, mobility, loyalty }
}
```

**行为**
- 选路：在连通图中按 `利润 = 卖价 − 成本 − 税负 − 风险` 选最划算路径，可切换陆/水/海
- 对官员反应：被加税 → 绕道 / 行贿买通 / 走私 / 与官员结成利益共同体
- 竞争：多个商人抢占同一线路，压价、抢货源
- 兴衰：大商帮（如晋商）可能因陆路衰败而衰落，海路商人（如希腊、意大利商）崛起

### 2.3 中央/外部力量（非智能体，制度引擎事件源）
- 朝廷/苏丹/沙皇/王室：下达税收指标、发动考成、册封/罢免
- 外部事件：条约、战乱、运河开通、铁路通车（改变路线成本，触发商路迁移）

## 3. 制度引擎（手写代码，硬约束）

制度是确定性规则，LLM 只能"在制度内钻空子"，不能改规则。

### 3.1 清朝流官制
- **任期**：三年（36 月）一任，到期触发换官事件
- **回避**：新官不得本籍任职、距原籍五百里内回避（代码判定）
- **捐纳**：可花费财富买官/升迁；可"打点"让指定亲戚成为下一任（成功率与打点金额、政绩挂钩）
- **考成**：任期结束时按"赋税达标度 + 政绩 + 贪腐暴露度"评估 → 升迁/平调/罢免

### 3.2 奥斯曼包税制
- **拍卖**：税收承包权定期公开拍卖，出价最高者得（官员间竞价）
- **期限**：iltizam 1–3 年短包；malikane 终身包、可世袭
- **榨取**：包税人实收与上缴定额的差额归己 → 天然激励过度征收
- **拥兵**：可动用军力强制征税，但过度会引发民变、招致中央清算

### 3.3 俄国职级制
- **职级**：14 级阶梯，靠"贸易额/功勋"晋升
- **抢功**：多个官员可能对同一政绩署名，需裁决功劳归属
- **忠诚**：过分贪腐若被沙皇察觉会降级/流放

### 3.4 奥地利重商主义
- **政策工具**：关税、特许状、垄断授权、补贴（制度化的"合法调控"）
- **考核**：国库收入与王室满意度

### 3.5 贸易线经济引擎（确定性结算）
- 每回合结算：各段税负/成本/风险 → 商人选路 → 总贸易量 → 各官员税基
- **过境博弈**：一地加税抬升整线成本 → 商人绕道 → 该地税基反而缩水
- **兴衰反馈**：陆路口岸（恰克图）vs 海路港口（敖德萨、的里雅斯特、苏伊士）的动态竞争

## 4. 回合结构（月为最小回合，年为叙事节拍）

```
每回合（1 个月）：
 1. 制度引擎：推进任期、触发换官/考成/拍卖事件
 2. 经济引擎：商人选路 + 结算上月贸易量与税基
 3. 智能体层：
    官员观察状态 → 生成 0~N 个动作（加税/贿赂/勾结...）
    商人观察状态 → 生成选路/行贿/绕道决策
 4. 制度引擎：裁决动作合法性，应用后果
 5. 经济引擎：更新贸易线参数（成本/风险/税负）
 6. 呈现层：写事件日志，刷新 UI
```

**换官事件（重点机制）**：清官三年到期 → 离任带走财富 → 触发"打点接班"判定（是否安插亲戚）→ 新官上任（带还本压力，急于回本）→ 形成周期性剥削节奏。

## 5. 涌现指标（代替"最优解"）

1. **谁富了**：官员离任带走的财富排行
2. **贸易线健康度**：总贸易量随时间的兴衰曲线
3. **腐败指数**：各地"实际征收 vs 上缴国库"差额占比
4. **家族延续**：包税人/捐纳官家族传承代数
5. **制度效率**：四地"国库实收 / 私囊占比"对比
6. **商路迁移**：陆路 vs 海路贸易量占比的时间曲线（恰克图衰落、敖德萨/的里雅斯特崛起）
7. **商人兴衰**：晋商等陆路商帮 vs 海路商人势力的此消彼长

## 6. UI 视觉重构（重点需求）

### 6.1 设计语言：19 世纪复古地图 + 蒸汽工业

**禁用 emoji**，图标一律用 CSS 几何图形 / SVG 线描 / 复古纹章符号替代。

**配色（羊皮纸 + 黄铜 + 氧化铜）**

| 角色 | 色值 | 用途 |
|---|---|---|
| 羊皮纸底 | `#F4E8C1` / `#FFF8E7` | 页面背景、卡片底 |
| 深羊皮纸 | `#D4C5A0` | 卡片阴影、边框 |
| 黄铜 | `#B87333` / `#C8A84E` | 按钮、边框、强调 |
| 氧化铜 | `#43B3AE` | 水路线条、次级强调 |
| 深棕皮革 | `#3C2415` / `#4E1E0E` | 主文字、标题 |
| 锈红 | `#8B3A1A` | 警示、税收、危险 |
| 羊皮纸墨 | `#704214` | 正文、说明 |

**字体（Google Fonts，复古衬线）**
- 标题/徽标：`Cinzel`（罗马铭刻大写感）或 `Playfair Display`
- 正文：`Spectral`（过渡衬线，长文可读）
- 电报/记录/标签：`Special Elite`（打字机风格）或 `Courier Prime`
- 装饰/花体：`UnifrakturMaguntia`（黑体 Fraktur，仅装饰用）

**视觉元素**
- 地图：羊皮纸纹理 + 复古罗盘玫瑰 + 齿轮/齿轮边框 + 手绘虚线商路
- 卡片：皮革缝合边、黄铜铆钉、雕花边框（Victorian filigree）
- 路线：陆路用锈红实线，水路用氧化铜虚线，海路用蓝灰虚线
- 状态：用机械表盘、气压计、齿轮转动表达（替代 emoji 的加载/状态）

## 7. 技术架构（纯静态前端 + 可迁移设计）

```
┌──────────────────────────────────────────────┐
│ 呈现层 UI（复古地图/节点面板/事件日志/指标曲线）    │
├──────────────────────────────────────────────┤
│ 编排层 Orchestrator（回合推进/换官/事件调度）      │
├──────────────────────────────────────────────┤
│ 制度引擎 Institution Engine（任期/回避/捐纳/考成/  │
│   包税拍卖/晋升 —— 纯代码硬约束）                 │
├──────────────────────────────────────────────┤
│ 经济引擎 Economy Engine（商人选路/税基/成本/风险） │
├──────────────────────────────────────────────┤
│ 智能体层 Agent Layer（官员 + 商人角色，私有状态）  │
│   · 每个角色独立 system prompt + 私有记忆         │
│   · DeepSeek API，结构化 JSON 契约               │
└──────────────────────────────────────────────┘
```

**关键复用/改造点（对照 1.0）**
- `advisor.js` 多智能体编排器 → 升级为"多角色编排器"（官员 N 个 + 商人 M 个，回合内批量决策）
- 共享决策记忆 → 拆分为按 `agentId` 隔离的私有记忆，随换官交接/清空
- 代码护栏 → 升级为制度引擎（钳制之外，新增任期/回避/捐纳/拍卖等规则判定）
- 错误卡片/重试 → 保留，扩展为多角色并发调用时的单角色失败隔离

### 7.1 技术栈演进决策（已定）

**2.0 用纯静态前端实现，3.0 再做前后端分离（Python 后端）。**

理由：
- 1.0 已验证纯前端能扛住多智能体编排（三角色流水线、决策记忆、护栏均在浏览器 JS 内跑通）。
- 2.0 增量（官员/商人多角色、制度引擎、回合制）本质是"JS 对象 + 函数"，浏览器可承载，只要角色规模克制（几十个角色、几百回合）。
- 先以最小成本验证"自私官员博弈"玩法，玩法对了再投入后端工程，避免在玩法未验证前背上基础设施成本。

**纯前端硬边界（需在 2.0 内妥协）**

| 边界 | 影响 | 应对 |
|---|---|---|
| API Key 裸奔 | Key 仍在 `config.local.js` | 演示阶段可接受；公开演示用临时 Key |
| localStorage 容量（约 5–10MB） | 撑不住多代博弈 + 完整事件日志 | 精简存储、定期归档旧事件、只存摘要 |
| 浏览器并发上限（同域约 6–8 个 fetch） | 一回合并发调几十个角色会慢 | 角色分批/串行、限制每回合同时决策的角色数 |

### 7.2 可迁移设计规范（2.0 必须遵守，否则 3.0 推倒重来）

**四原则**

1. **引擎与 UI 解耦**：制度引擎、经济引擎、智能体逻辑写成**不碰 DOM 的纯 JS 模块**；UI 只读引擎状态、单向渲染。未来迁移 = 引擎模块整体搬到 Python，UI 一行不动。
2. **状态可序列化**：官员、商人、贸易线、事件日志全部用纯 JSON 结构；未来直接映射到 pydantic / SQLite，数据结构不变。
3. **LLM 调用封装单一接口**：所有角色共用一个 `callLLM(role, prompt)` 函数（内部直连 DeepSeek）；3.0 时改为 `fetch('/api/llm')`，其余代码零改动。
4. **回合调度器独立**：回合循环（制度推进 → 经济结算 → 角色决策 → 事件）独立为 orchestrator 模块；3.0 时整体搬到 FastAPI 的异步任务。

**目录约定（强制引擎/UI 边界）**

```
js/engine/          纯逻辑，禁止 document/window/DOM 操作，禁止依赖 UI
  institution.js    制度引擎（任期/回避/捐纳/考成/包税拍卖/晋升）
  economy.js        经济引擎（商人选路/税基/成本/风险结算）
  agents.js         智能体角色（官员/商人私有状态 + 决策生成）
  orchestrator.js   回合调度器
  llm.js            LLM 调用单一接口（callLLM 封装）
  state.js          状态定义 + 序列化（纯 JSON）
js/ui/              渲染与交互，只读 engine 状态
  map.js            复古地图渲染
  charts.js         指标曲线
  log.js            事件日志视图
  panel.js          官员/商人面板
  style/            复古 UI 样式
```

**铁律**：`js/engine/` 内禁止出现 `document`、`window`、`localStorage`、任何 DOM 操作与浏览器 API；持久化通过 `state.js` 的统一读写接口完成。违反此边界 = 迁移债务，code review 时一律打回。

# 2026-09-25

## 排查并修复"卡在一月 + Chrome 地图 access block"

### 根因（Playwright + 系统 Chrome headless 实测复现）
1. **卡在一月 = 三因叠加**：
   - `state.js` 初始 `monthIndex: 0`，月份公式 `((monthIndex-1)%12)+1` 第一次推进后仍算出 1 月（off-by-one）
   - `app.js` 的 `advance` catch 里 `renderError()` 画出的错误卡片被 `finally` 的 `elStatus().innerHTML=''` 立即抹掉 → 所有 LLM 失败静默回滚
   - `llm.js` 的 `max_tokens: 800`：deepseek-flash 是推理模型，思考 token 计入输出额度，长 prompt 下思考完就没额度输出 → "DeepSeek returned empty content"（实测复现）
2. **地图 access block**：`tile.openstreetmap.org` 对大陆 IP 拦截；`unpkg.com` CDN 也不稳

### 修复
- `index.html`：Leaflet 1.9.4 本地化到 `lib/leaflet/`（不再走 unpkg）；加 SVG data-URI favicon 消 404
- `map.js`：瓦片源换高德 `webrd0{s}.is.autonavi.com`（大陆直连，GCJ-02 偏移在 zoom 4-6 可忽略）
- `state.js`：初始 `monthIndex: 1`；`restore()` 对旧档 monthIndex===0 做迁移
- `agents.js`：`_extractJSON()` 剥离 ```json 包裹再 parse（官员/商人共用）；`decideMerchant` 在 rule 模式或 aiMerchantEnabled=false 时不调 LLM
- `llm.js`：删除 `max_tokens: 800`（用户明确要求：1.0 就没限制）
- `app.js`：`advance` 重写为逐月推进（每月独立快照，失败只回滚当月、保留已完成月份）；错误卡片不再被 finally 清掉；推进期间按钮禁用显示"推进中…"；`agentResult` 兼容商人 action 字段
- `panel.js` + `app.js`：**API Key 网页手动输入**（password 输入框，localStorage `cku2_api_key` 持久化，优先于 config.local.js，清空则回退）；401 错误卡片提示去输 Key；AI 商人独立开关（rule 模式下禁用）

### 验证
- smoke-2.0.js 全过（规则模式 40 回合、显式抛错）
- 浏览器回归：地图高德瓦片 ✓ / 规则模式推进 1→2 月 ✓ / 快进六月 2→8 月 ✓ / 注入 500 错误卡片显示且保留 ✓
- 真实 LLM 端到端：真实官员 prompt 5.2s 返回，解析出合法决策 ✓

### 调试方法论（可复用）
- Playwright-core（`npm install playwright-core`）+ 系统Chrome `executablePath: 'C:/Program Files/Google/Chrome/Application/chrome.exe'` + `args:['--no-proxy-server']`（本机代理会拦 127.0.0.1）
- 后台 server 必须与测试同一条 bash 命令启动（跨命令后台进程会被清理）
- `page.route('**/api.deepseek.com/**')` 注入失败是验证错误 UI 的利器

## Phase 1.5 设计研究（未写代码，方案见 docs/phase1.5-design.md）
用户提出三项改动并要求先研究后动手：
1. 品级 + 含权量：真实清制品级表（都统从一品→同知正五品，rankScore 比较）；powerIndex 0-100 动态公式（品级40%+职务25%+贸易量25%+政治资本10%）；制度性上下级硬编码（库伦/察哈尔两系统）；孝敬=自动陋规结算（非 LLM 动作）；含权量调制暴露概率/考成/分账份额
2. 勾结分账：collude 改双边契约（官员或商人均可发起，带 target）；标的=当月实际避税额；官份额=0.35+0.003×powerIndex（35%~65%）；契约按月延续、换官即作废；事件日志一行一账（官得/商留精确到两）
3. 商人现金流（地基）：每月 shipment=min(capital×0.8,容量)→收入−实缴税−打点−风险损失=净利→capital 涨落；capital<100 破产退出、3月后新商人进场；totalVolume/税基改为真实聚合
待用户拍板 5 项（孝敬方式/契约延续/破产策略/品级数值/风险模型），均有推荐项
